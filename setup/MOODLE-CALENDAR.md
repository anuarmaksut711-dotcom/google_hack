# Moodle без REST API: личный календарь

Локальный режим читает стандартный экспорт iCalendar из AITU Moodle напрямую.
Нужны доступ студента к экспорту календаря и его личная ссылка. Администратор,
Google Drive, Gemini и Google Cloud для этого режима не требуются.

В Moodle: Dashboard → Import or export calendars → Export calendar → All events →
Recent and next 60 days → Get calendar URL. Сохраните адрес в
`.campuspulse-local/moodle-calendar-url.txt`. Это секретная ссылка: не добавляйте
её в Git, переписку, команды запуска или настройки клиентского JavaScript.

Установка дополнительного парсера в существующее окружение:

```powershell
./.tools/uv/bin/uv.exe pip install --python .venv-agent/Scripts/python.exe 'icalendar==6.3.2'
```

В `pyproject.toml` зависимости этого источника также объявлены в extra `calendar`.
Для новой установки нужны extras `demo,calendar` и Python 3.12.

Из корня проекта в PowerShell запустите, заменив число настоящим Moodle user ID:

```powershell
./run-moodle-calendar.ps1 -UserId 12345
```

Откройте `https://127.0.0.1:8959/local`. У сервера локальный самоподписанный
сертификат: предупреждение браузера подтверждает сам пользователь. Нажмите
«Открыть мои дедлайны». Этот вход создаёт сессию только локального CampusPulse;
он не является Google-входом или повторным входом в Moodle. Не публикуйте этот
режим через туннель или общедоступный сервер. Процесс слушает только 127.0.0.1.

## Какие данные доступны

- События, названия предметов, описания и сроки в пределах выбранного экспорта.
- Записи Attendance исключаются из списка дедлайнов. Другие события сохраняются
  как события календаря, без выдуманных идентификаторов заданий.
- Оценки и статусы сдачи отсутствуют. Наличие прошедшего срока не означает,
  что работа не сдана. Ссылки на задания выводятся только при наличии точного URL
  активности в поле URL события, а не по упоминаниям в описании.
- Планирование и запись в Google Calendar в этом режиме не подключены.

В интерфейсе будущие сроки показаны отдельно от свёрнутых разделов «Прошедшие
сроки» и «Выполнено вами». Прошедший срок определяется текущим временем, а не
статусом сдачи. Кнопки «Отметить выполненным» и «Вернуть в работу» сохраняют
личную отметку в соседнем с кешем файле `moodle-calendar-cache-task-statuses.json`.
Она привязана к аккаунту, источнику и UID события, переживает обновление экспорта
и перезапуск, не меняет Moodle и не подменяет неизвестный статус сдачи.
Gemini не получает работы, помеченные выполненными в CampusPulse.

Чтение выполняется при старте сервера, открытии страницы и нажатии «Обновить
задания», не чаще одного запроса в минуту. Это не фоновая синхронизация после
остановки процесса. Экспорт `recentupcoming` ограничен периодом, выбранным Moodle;
он не обещает все задания за весь период обучения.

Последний успешно полученный снимок хранится в
`.campuspulse-local/moodle-calendar-cache.json`. После ошибки обновления он
сохраняется, время последнего успеха не изменяется; через 30 минут интерфейс
показывает устаревание. Изменение секретной ссылки инвалидирует старую привязку
кеша. Ссылка проверяется по HTTPS, точному домену, пути и Moodle user ID.
Редиректы, большие ответы, повторяющиеся события и неверный формат отклоняются.
Пароли, cookies Microsoft/Moodle и REST API-токены не используются.

Чтобы остановить чтение, завершите процесс сервера. Если личная ссылка раскрыта,
отзовите/обновите ключ экспорта средствами Moodle и замените локальный файл.

Проверки: `tests/lms/test_calendar_feed.py`, а также существующие Moodle/web тесты.
Реализация использует пакет `icalendar`; код ReMoodle не копировался. Подход
подтверждён [публичной инструкцией ReMoodle](https://github.com/remoodle/heresy/blob/trunk/docs/guide/moodle-calendar-url.md).

## Gemini и план в чате

Создайте Gemini API key в Google AI Studio в проекте с Free tier, без подключения
платного биллинга. Наличие бесплатной квоты проверяется реальным запросом: доступ
и лимиты зависят от аккаунта и модели. Пример несекретных настроек для модели,
для которой опубликован бесплатный тариф:

```json
{"provider":"gemini_api","model":"gemini-3.5-flash-lite"}
```

Сохраните только provider/model в `.campuspulse-local/chat-moodle-gemini.json`.
Запустите рядом с календарём отдельный локальный процесс, подставив свой user ID:

```powershell
./run-moodle-calendar.ps1 -UserId 12345 -Port 8960 -ChatTarget ./.campuspulse-local/chat-moodle-gemini.json -PromptGeminiKey
```

Вставьте ключ в скрытый запрос PowerShell. Скрипт передаёт его дочернему Python
через окружение и не сохраняет в файлы или аргументы командной строки. После
остановки прежнее значение переменной процесса восстанавливается. Откройте
`https://127.0.0.1:8960/local`, создайте локальную сессию кнопкой входа и напишите
в чате, например: «Составь план до воскресенья. Могу заниматься с 19 до 21,
на каждую работу осталось примерно 2 часа». Эти часы и длительности — ввод
пользователя, они не выводятся из календаря Moodle.

Добавьте `-Background`, чтобы после скрытого ввода ключа запустить отдельный
фоновый процесс. После сообщения о фоновом запуске окно PowerShell можно закрыть.
Файлы `calendar-8960.pid`, `calendar-8960.stdout.log` и `calendar-8960.stderr.log`
создаются в `.campuspulse-local/`; значение API-ключа в них не записывается
лаунчером. Перед повторным запуском убедитесь, что прежний процесс на этом порту
остановлен. Перезагрузка компьютера всё равно завершит процесс: для нового
запуска ключ нужно ввести снова, поскольку он не сохраняется на диск.

Перед каждым запросом чата адаптер пытается обновить Moodle с общим ограничением
одного чтения в минуту. Gemini получает текущие дату/часовой пояс, названия
заданий, названия предметов и сроки. Описания, имена преподавателей, ссылка
экспорта, Moodle user ID, пароли и API-ключи в контекст модели не передаются.
Чат ограничен первыми 99 событиями по срокам; при превышении модель получает
явное уведомление об ограничении. Предупреждения об устаревании сохраняются.

План является рекомендацией в чате. Статусы сдачи и доступные часы не выдумываются;
для составления реалистичного плана ассистент уточняет эти данные. Запись плана
в Google Calendar или Moodle не подключена. История чата и локальные сессии
хранятся в памяти процесса и сбрасываются при перезапуске.

В Free tier запросы и ответы могут использоваться Google для улучшения продуктов:
[тарифы и условия](https://ai.google.dev/gemini-api/docs/pricing).

## Отдельные кабинеты с Google-входом

Новый режим запускается отдельно от однопользовательского сервера выше.
Кнопка Google использует OAuth Web Client ID, а не ключ Gemini. В Google Auth
Platform создайте приложение CampusPulse с аудиторией External и клиентом
Web application. Для локального запуска добавьте Authorized JavaScript origin
`https://127.0.0.1:8961` без пути. Redirect URI для popup-входа не требуется.
Сохраните только публичный Client ID в
`.campuspulse-local/google-signin-client-id.txt`; Client Secret не используется.

```powershell
./run-multiuser.ps1 -PromptGeminiKey -Background
```

Откройте `https://127.0.0.1:8961/login`. После Google-входа новый пользователь
попадает на `/account`, вставляет личную ссылку Get calendar URL из Moodle AITU
и открывает свои задания. Менять ссылку можно через «Моё подключение Moodle».
Google-вход сам по себе не предоставляет доступ к Moodle. Поддерживается
календарный экспорт AITU; пароль Moodle приложение не запрашивает.

Сервер проверяет подпись Google ID token, audience, issuer, срок и одноразовый
nonce, затем создаёт отдельную ResourcePolicy по неизменяемому Google subject.
Все закрытые обработчики повторно проверяют серверную сессию; выбрать другого
владельца через query/body нельзя. Проверенный Google subject, а не email,
задаёт пространство записей, отметок и истории. Перед созданием кабинета
dispatcher проверяет ID token; штатный WebAuth проверяет его повторно при входе.
Локальных кнопок входа и обхода Google-проверки в этом режиме нет.

Аккаунты, сессии, ссылки Moodle и переписка сохраняются в зашифрованных
документах SQLite в `.campuspulse-local/multiuser/`. Сохраните каталог вместе
с `storage.key`: без этого ключа восстановление документов невозможно. Кэш
календаря и локальные отметки лежат в отдельных каталогах по владельцу и
привязке ссылки. Они не отправляются другим пользователям. История чата
переживает повторный вход и перезапуск; сохраняется существующий предел
40 запросов на диалог. Gemini API key по-прежнему существует только в памяти
запущенного процесса и не сохраняется в SQLite или файлах.

Старый локальный календарь и переписка не назначаются первому вошедшему
Google-аккаунту. Перенос личных отметок требует явной привязки к проверенному
владельцу; новый пользователь начинает со своим календарём.

Это локальный сервер: `127.0.0.1` недоступен с устройств друзей. Для общего
доступа нужен отдельный HTTPS deployment с постоянным хранилищем и точным
публичным origin в OAuth-клиенте. Текущий CLI слушает только loopback и не
публикует компьютер. Создание OAuth-клиента не включает платный Gemini billing.
Если используется один API-проект, его квота Gemini общая для всех кабинетов.
При исчерпании бесплатной квоты новый ответ модели недоступен, сохранённые
задания и переписка остаются в приложении. Платный tier меняет эти условия;
автоматический переход на платные модели приложением не предусмотрен.
