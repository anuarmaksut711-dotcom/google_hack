# Чаты и проекты

Боковая панель разделена на «Проекты» и «Чаты». Проект объединяет диалоги по
предмету или задаче; общие файлы, инструкции и память проекта в этот этап не входят.
Кнопки «Новый чат» и «+» у проекта открывают локальный черновик. Повторное нажатие
возвращает в тот же черновик, сохраняя текст; пустые записи в каталоге не создаются.
Чат регистрируется при первой отправке сообщения, сразу в выбранном проекте.
Новые диалоги получают короткое название по теме первого сообщения через настроенную
модель. Если генерация названия недоступна, используется начало сообщения; ответ
ассистента при этом сохраняется. Ручное название сохраняется.
Внутри списка диалоги упорядочены по последней активности.

Черновики каждого чата сохраняются в `sessionStorage` текущей вкладки и переживают
обновление страницы. Они привязаны к проверенной сессии и очищаются при выходе.
Временная ошибка обновления не удаляет черновики. После восстановления завершённого
запроса его текст не остаётся в поле для повторной отправки; новый отредактированный
текст сохраняется. Пока идёт голосовой ввод, переключение чата заблокировано.
Переход «Ассистент» возвращает к текущему диалогу.

Каталог записывается в формате `chat-workspace-v3`. Чтение прежних `v1` и `v2` сначала
проверяет целостность по их исходным схемам, затем переносит данные. Старые ручные
названия и ключи историй сохраняются; отдельная массовая миграция не требуется.

## Сохранённые действия и API

Кнопка «Новый чат» находится наверху боковой панели. У каждого чата своя история;
папка группирует чаты и не меняет доступ к ним. Меню «⋮» у строки чата открывает
переименование, перемещение в проект / из проекта и удаление. Действие относится к этой строке,
даже если открыт другой чат. Постоянных форм настройки в боковой панели нет.
Переименование открывает нативное модальное окно с текущим выделенным названием:
Enter сохраняет, Escape и «Отмена» закрывают без изменений. Неизменённое и пустое
название нельзя отправить. После закрытия фокус возвращается к строке чата.
Создание проекта доступно по иконке у заголовка «Проекты». Меню проекта позволяет
изменить его название, создать в нём чат или удалить проект. Проекты одноуровневые и сворачиваются.
При удалении проекта все его чаты переходят в общий список; их названия и истории
сохраняются. Удаление чата убирает его из каталога и стирает содержимое текущей
записи истории. Удалять можно и старый «Первый чат», и пустые чаты.

Старая переписка доступна как «Первый чат»: её ключ хранилища не изменяется.
Переименование чата и перемещение не меняют историю. Страницы имеют адреса
`/#chat/<chat_id>`; обновление страницы и Back/Forward сохраняют выбранный чат.
Несохранённые черновики используют `/#new` и `/#new/<folder_id>`; при первой отправке
адрес заменяется адресом сохранённого чата. Ключ регистрации связан с ключом первой
отправки, поэтому повтор после потерянного ответа не создаёт второй чат.
Черновики сохраняются при переключении между чатами и обновлении вкладки.

В многопользовательском Moodle-приложении каталог и истории привязаны к проверенному
владельцу и сохраняются при повторном входе. В существующих конфигурациях с историей
на сессию сохраняется прежняя граница сессии. В облаке используется существующий
адаптер Firestore; новых ключей, индексов и сервисов не требуется.

`GET /api/chat/workspace` возвращает каталог текущего пользователя.
Изменения идут через `POST /api/chat/workspace` с CSRF, номером ревизии и ключом
идемпотентности. Конкурирующее изменение требует перечитать каталог. Повтор создания
с тем же ключом не создаёт дубликат даже после вытеснения старой квитанции.
Поддерживается до 120 чатов и 40 проектов, название — до 80 символов.
Поля API `folder_id`, `folders` и действия `create_folder` / `rename_folder`
сохранены для совместимости. `updated_at` задаётся сервером и используется для
сортировки чатов. Повтор отправки с тем же ключом не меняет активность повторно.

Действия `delete_chat` и `delete_folder` принимают только `item_id`, `request_key`
и `revision` вместе с `action`. Удаление и перенос чатов из удаляемого проекта
выполняются одной транзакцией. Удалённые идентификаторы сохраняются как служебные
отметки без текста переписки в `cp_chat_deleted_items`; сама запись удалённой
истории заменяется такой же отметкой. Это запрещает позднему повтору создания
восстановить удалённый чат или проект. Проверка каталога входит в транзакции чтения
и записи истории, поэтому ответ модели, пришедший после удаления, не возвращает
историю. Старая ссылка и новые отправки в удалённый чат получают отказ в доступе.
Удаление относится к активным записям приложения; резервные копии управляются
настройками хранения облачной платформы.

Для истории `GET /api/chat` принимает единственный необязательный `chat_id`.
Для отправки `POST /api/chat` принимает `chat_id` в JSON. Отсутствие поля сохраняет
прежний чат. Сервер проверяет принадлежность чата и папки владельцу; ввод браузера
не определяет владельца. Статусы, запрет повторного вызова неизвестного ответа,
проверка сессии и лимит истории действуют отдельно для каждого чата.

Чаты используют существующего агента и общий разрешённый контекст заданий/календаря;
история другого чата в запрос модели не включается. Создание папки, переключение и
переименование не вызывают Gemini и не подтверждают изменения Calendar.

Проверки: `tests/web/test_chat_workspace.py`, существующие chat/UI/multiuser tests.
Локальный браузерный стенд использует синтетическую личность, хранилище и ответы;
он не доказывает облачный деплой, качество Gemini или транзакции реального Firestore.
