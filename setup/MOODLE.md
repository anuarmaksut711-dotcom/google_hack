# AITU Moodle: задания и баллы в CampusPulse

Интеграция получает данные из `https://lms.astanait.edu.kz` через Moodle REST API.
Она читает доступные студенту задания и тесты, описания, сроки, статусы сдачи,
опубликованные оценки за работы и итоговые баллы по предметам. Скрытая оценка или
отсутствие опубликованной оценки не превращается в ноль. Продление срока задания
учитывается, если Moodle возвращает его в статусе сдачи.

Облачный worker сохраняет последний полный снимок в Firestore. Cloud Scheduler
вызывает его по расписанию, по умолчанию раз в 15 минут, даже когда браузер и
CampusPulse закрыты. При открытии страницы сначала показывается сохранённый
снимок, затем запрашивается обновление. Повторные запросы из приложения ограничены
одним запуском в 60 секунд. Это периодическая синхронизация, а не мгновенная
доставка каждого изменения преподавателя.

## Граница текущей реализации

**Одна установка настроена на одного студента.** Moodle user ID привязан к
`application.student.trusted_user_id` и Google subject в
`application.student.allowed_signin_principal`. Это не готовая регистрация
произвольных студентов: для общего запуска потребуется отдельное подключение и
хранение привязок каждого пользователя. Нельзя раздавать текущую конфигурацию
нескольким студентам как личные кабинеты.

Moodle-режим показывает реальные задания и баллы. Автоматическое планирование
для этого источника отключено до добавления отдельных оценок оставшегося времени
на работу. Данные из старой Google Sheets не подставляются вместо Moodle-заданий.
API-ключ Gemini для чтения Moodle и фонового worker не требуется.

Поддерживаемые пределы одного снимка: 100 курсов, 500 заданий/тестов и до 800 КБ
вместе с описаниями и служебными полями. Если ответ превышает эти пределы,
синхронизация сохраняет предыдущие данные и сообщает об ошибке; неполный список
не выдаётся за успешно обновлённый.

## Что нужно от студента и администратора LMS

1. Проверить, разрешены ли web services и REST в университетском Moodle. Успешный
   вход в официальное приложение Moodle помогает диагностике, но сам по себе
   не выдаёт токен для нашего сервиса и не подтверждает доступность всех функций.
2. Создать отдельный **сервис только для чтения**, разрешённый этому студенту,
   с функциями из таблицы ниже. Токен должен принадлежать самому студенту; доступ
   преподавателя или администратора приложению не нужен. Выдача токена зависит
   от настроек и прав AITU Moodle; иногда это может сделать только администратор.
3. Получить числовой Moodle user ID этого же студента для `expected_user_id`.
   Это не email, имя пользователя или Google subject. Worker сверяет его с
   `userid`, возвращённым `core_webservice_get_site_info`, до чтения курсов.
4. Настроить Google-вход в CampusPulse для этого студента. Значение
   `allowed_signin_principal` имеет вид `https://accounts.google.com#GOOGLE_SUB`,
   где `GOOGLE_SUB` — проверенный неизменяемый `sub` Google ID token, не email.

Точный allowlist находится в `src/campuspulse_recovery/lms/client.py`,
`READ_FUNCTIONS`. Нужны все восемь функций; неполный сервис не считается успешным
подключением:

| Функция | Для чего нужна |
| --- | --- |
| `core_webservice_get_site_info` | Проверка владельца токена и доступных функций |
| `core_enrol_get_users_courses` | Курсы студента |
| `core_course_get_contents` | Проверка доступности разделов и работ этому студенту |
| `mod_assign_get_assignments` | Задания, описание и сроки |
| `mod_assign_get_submission_status` | Статус сдачи и продление срока |
| `gradereport_user_get_grade_items` | Опубликованные оценки и итоги по предметам |
| `mod_quiz_get_quizzes_by_courses` | Тесты и сроки закрытия |
| `mod_quiz_get_user_attempts` | Статусы попыток тестов |

Ограничения роли студента сохраняются: например, при отключённом преподавателем
журнале оценок курс не получает выдуманные баллы. Лента `.ics` календаря не заменяет
этот API: она может передавать сроки, но не даёт нужные статусы сдачи и оценки.

Пароль Moodle приложению не передаётся. Не вставляйте токен, пароль или полный
Google ID token в чат, Git, журнал терминала или аргументы команд. Университетский
вход через OpenID Connect не нужно обходить автоматическим вводом пароля.

## Секрет и конфигурация Google Cloud

Нужны существующий Google Cloud project, включённый биллинг, Firestore, Cloud Run,
Secret Manager и Cloud Scheduler, а также права на развёртывание. Базовая
подготовка описана в `setup/CONNECTING.md`.

В Google Cloud Console создайте отдельный Secret Manager secret для Moodle
токена. Вставляйте значение только в защищённое поле секрета; не сохраняйте его
в JSON настроек. Запомните **номер версии**, например `1`, и укажите полный путь
`projects/PROJECT_ID/secrets/campuspulse-moodle-token/versions/1`.
Ссылка `latest` для этой интеграции не принимается. Изменение/истечение токена
требует новой версии секрета, обновления ссылки в настройках и развёртывания.

Скопируйте уже заполненный базовый `cloud-settings.json` в новый файл внутри
`.campuspulse-local/`, например `cloud-settings.moodle.json`, и добавьте верхнее
поле `moodle`. Остальные настройки сохраняйте. Пример ниже — схема замены значений,
не готовая конфигурация:

```json
{
  "moodle": {
    "site_url": "https://lms.astanait.edu.kz",
    "expected_user_id": 12345,
    "token_secret_reference": "projects/PROJECT_ID/secrets/campuspulse-moodle-token/versions/1",
    "sync_origin": "https://campuspulse-moodle-PROJECT_NUMBER.REGION.run.app",
    "sync_service_account": "campuspulse-lms-worker@PROJECT_ID.iam.gserviceaccount.com",
    "scheduler_service_account": "campuspulse-lms-scheduler@PROJECT_ID.iam.gserviceaccount.com",
    "interval_minutes": 15,
    "stale_after_minutes": 30
  }
}
```

Замените `12345` настоящим Moodle user ID. `PROJECT_ID`, `PROJECT_NUMBER` и `REGION`
должны совпадать с базовыми настройками развёртывания; используется регион web
Cloud Run. Worker и Scheduler должны иметь два разных service account в том же
проекте, отличных от backend, agent, MCP и build service account.
Интервал допускает 5, 10, 15, 20, 30 или 60 минут; порог устаревания должен быть
не меньше интервала и находиться в пределах 10–180 минут.

Базовая схема приложения пока также требует старые поля Sheets/Calendar и
`working_hours`; сохраните существующие корректные значения. Для запуска только
Moodle список `working_hours` может быть пустым. Они не означают,
что Moodle-режим использует Sheets как источник работ или строит по ним план.

## Подготовка и развёртывание

Скрипты запускаются из корня проекта в PowerShell 7. Сначала подготовьте/обновите
базовое облачное развёртывание с **этим же** Moodle-enabled файлом настроек через
`deploy/deploy-cloud.ps1 -MoodleOnly`; затем запускайте `deploy/deploy-moodle.ps1`. У web backend
и worker должна быть одна и та же версия конфигурации. Значение токена монтируется
только в приватный worker, не в браузер и не в web backend.

```powershell
./deploy/deploy-cloud.ps1 `
  -InputsPath ./.campuspulse-local/cloud-run-inputs.json `
  -SettingsPath ./.campuspulse-local/cloud-settings.moodle.json `
  -MoodleOnly
```

Эта команда по умолчанию только печатает локальный план. После проверки добавьте
`-Mode Deploy`: скрипт развернёт только web backend, а не agent/MCP, и не потребует
ключ Gemini. Без ключа Gemini чат недоступен, Moodle продолжает работать.
Проверьте настройки OAuth Web client: разрешённый JavaScript origin должен
совпадать с `backend_origin`.

После настоящего развёртывания вывод содержит `image` и `settings_version`.
Используйте `image` как `ImageDigest` следующего скрипта, а имя секрета настроек
`campuspulse-cloud-settings` вместе с полученным `settings_version` как
`SettingsSecret`. Не подставляйте произвольную старую версию: web и worker должны
читать одинаковую конфигурацию.

Для Moodle-скрипта требуются:

- `InputsPath`: заполненный `.campuspulse-local/cloud-run-inputs.json`;
- `SettingsPath`: заполненный `.campuspulse-local/cloud-settings.moodle.json`;
- `SettingsSecret`: имя и **числовая версия** Secret Manager секрета этих настроек,
  например `campuspulse-cloud-settings:3`;
- `ImageDigest`: уже собранный образ из настроенного Artifact Registry,
  с окончанием `@sha256:` и 64 шестнадцатеричными знаками.

Ниже переменные содержат только ссылки и идентификаторы, не значения секретов:

```powershell
$moodleSettingsSecret = 'campuspulse-cloud-settings:3' # реальная версия настроек
$moodleImageDigest = 'REGION-docker.pkg.dev/PROJECT_ID/REPOSITORY/IMAGE@sha256:REPLACE_WITH_64_HEX_DIGEST'
./deploy/deploy-moodle.ps1 `
  -InputsPath ./.campuspulse-local/cloud-run-inputs.json `
  -SettingsPath ./.campuspulse-local/cloud-settings.moodle.json `
  -SettingsSecret $moodleSettingsSecret `
  -ImageDigest $moodleImageDigest
```

Без `-Mode Deploy` выполняется только локальная подготовка плана: облачные команды
и запросы в LMS не выполняются. Образ в примере нужно заменить реальным digest
до запуска. После проверки плана повторите команду с `-Mode Deploy`.

Deploy создаёт отдельный приватный `campuspulse-moodle` Cloud Run service, выдаёт
worker доступ к нужным секретам и настроенной базе Firestore, разрешает вызов
только backend и Scheduler service account и создаёт задание
`campuspulse-moodle-sync`. Scheduler использует OIDC; его audience совпадает с
`sync_origin`. Расписание живёт в Google Cloud и не зависит от открытого браузера,
процесса на ноутбуке или текущей браузерной сессии студента.

Приложение можно открыть после Google-входа в существующий облачный web backend.
Локальная страница `/demo` продолжает использовать демонстрационные данные и не
подтверждает подключение настоящего Moodle аккаунта.

## Как подтвердить работу с настоящим аккаунтом

Локальный прогон без токенов (из корня проекта, в подготовленном SDK-окружении):

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
./.venv-agent/Scripts/python.exe -m pytest tests/lms tests/web tests/security -q
```

Он включает ответы Moodle через HTTP MockTransport, постоянный кеш после
перезапуска, фоновое изменение оценки без браузера, проверку сессии/CSRF и
локальный `Prepare` PowerShell-скриптов. Пропускать `PYTHONPATH` здесь нельзя:
ранее установленный wheel может предшествовать новым исходникам.

Проверка 19 октября 2026: 401 тест Moodle/web/security прошёл; расширенная
регрессия и две проверки ADK доводят общий результат до 1314 успешных тестов.
Десять проверок реального Firestore emulator пропущены, так как он не настроен.
Интерфейс отдельно проверен в браузере на синтетических данных при 1280×720
и 390×844. Это не подтверждение доступа к реальному LMS или Google Cloud.

Автоматические тесты используют подставные ответы API и не доказывают наличие
разрешений в AITU. После выдачи настоящего токена и развёртывания:

1. В Google Cloud Console откройте Scheduler job `campuspulse-moodle-sync` и
   выполните «Run now». Проверьте успешное выполнение и время последней успешной
   синхронизации в CampusPulse. `/healthz` означает только живой процесс.
2. Сверьте с Moodle несколько заданий и тестов: предмет, описание, срок,
   продлённый срок при наличии, черновик/сдачу и опубликованные баллы. Сверьте
   также опубликованный итог по предмету. Не публикуйте скриншоты с чужими данными.
3. Закройте CampusPulse. После реального изменения задания или опубликованной
   преподавателем оценки дождитесь следующего запуска Scheduler. При следующем
   открытии должен сразу отобразиться обновлённый снимок с новым временем
   синхронизации. Искусственно менять оценку для проверки не требуется.
4. Проверьте, что другой Google аккаунт не получает данные настроенного студента.

При временной ошибке LMS последний полный снимок сохраняется. Время успешного
обновления не продлевается из-за неудачного запроса. По умолчанию через 30 минут
данные считаются устаревшими; интерфейс сообщает об этом. Ошибки доступа,
несовпадение Moodle user ID и недоступные функции не должны превращаться в
успешную синхронизацию с пустым списком.

Чтобы остановить фоновые обращения, приостановите Scheduler job. Для полного
отключения отзовите Moodle токен и уберите Moodle-конфигурацию из следующего
развёртывания; удаление вкладки или выход из CampusPulse не останавливают серверное
расписание. Решение об удалении сохранённых учебных данных принимается отдельно.

## Короткий список того, что передать команде

Можно передать без секретов: Moodle user ID, Google subject для привязки,
Google Cloud project ID/number, выбранный регион, ссылки на числовые версии
Secret Manager и список разрешённых API функций. Сам токен студент/администратор
вносит в Secret Manager, а пароль остаётся только у владельца аккаунта.

Официальные материалы: [AITU Moodle](https://lms.astanait.edu.kz/login/index.php),
[настройки доступа Moodle для приложений](https://docs.moodle.org/en/Moodle_Mobile_guide_for_admins),
[вызов Cloud Run из Scheduler](https://docs.cloud.google.com/run/docs/triggering/using-scheduler).
