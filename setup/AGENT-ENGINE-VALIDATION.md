## Что покрыто

- Схема custom operation получена настоящим Vertex SDK 1.165.1.
- Сериализация переносит только проверенную конфигурацию.
- Неверные service ID-токены, истёкшие/использованные grants и отозванная сессия
  отклоняются до вызовов инструментов.
- Реальная цепочка backend → локальный AgentEngineRuntime → ASGI worker → ADK →
  localhost MCP → solver/approval/apply/verify проходит для Moodle.
- Повтор завершённого apply не создаёт дополнительных событий.
- Таймаут, отмена и ошибки закрывают ресурсы без автоматического повтора.
- Регрессия настоящего MCP logging подтверждает подавление приватного маркера.
- Проверяются wheel metadata/RECORD/исходники, hash-pinned lock, приватные права
  bundle и отсутствие перезаписи существующего каталога.
- `pip --dry-run --no-index --require-hashes` подтверждает установку продуктового
  wheel по строке, сформированной в deployment requirements.

Модель, Calendar, вход в аккаунт и облачное хранилище сквозных runtime-тестов
синтетические. Настоящий Firestore SDK отдельно проверяется с локальным эмулятором.
Offline CLI и установленный wheel проверены с запретом сетевых запросов и ADC.

## Что не подтверждено

Развёртывание в GCP, IAM, регион/модель, реальные credentials, установка пакетов
на удалённой платформе, достижимость MCP и подключение backend через SDK требуют
проверки команды подключений. Ресурс `reasoningEngines/...` и живое демо не создавались.
Поэтому критерий кейса «успешный Agent Engine deployment и доступный API» пока
остаётся открытым, несмотря на готовый серверный runtime.
