# Напоминания о дедлайнах в Telegram

Пользователь подключает Telegram в **Настройки → Уведомления в Telegram**:
нажимает «Подключить Telegram», открывает выданную ссылку, нажимает Start у бота,
возвращается на сайт и нажимает «Подтвердить и включить».
Выключатель в настройках и команда `/stop` отключают отправку.

## Настройка администратором

Скрипты в `deploy/telegram` предназначены для существующего Cloud Run сервиса
`campuspulse` в проекте `project-e25873c6-e889-40bb-86d`, регионе `us-central1`,
с Firestore `campuspulse-calendar` и конфигурацией gcloud `campuspulse-t11`.
Сначала разверните версию приложения с Telegram-маршрутами.

1. Создайте бота через [BotFather](https://t.me/BotFather).
2. Скопируйте `deploy/telegram/token.txt.example` в `deploy/telegram/token.txt`.
   Вставьте в него только токен, одной строкой, и сохраните.
3. Запустите **«Подключить Telegram.cmd»** двойным щелчком. Можно также запустить
   `configure-telegram.ps1` через PowerShell; при пустом файле он предложит скрытый ввод.
4. Для установки фонового расписания запустите `provision-scheduler.ps1` один раз
   из консоли с настроенным gcloud. В текущем облачном проекте расписание уже настроено.

Скрипт сохраняет токен и отдельный секрет webhook в Secret Manager, подключает
их конкретные версии к сервису, проверяет новую ревизию перед переключением
трафика и регистрирует webhook. После успешной настройки локальный `token.txt`
очищается. Токены не следует добавлять в исходники или коммиты; файл исключён из Git.
При сбое файл остаётся для повторного запуска. Проверка без токена и без изменений:
`configure-telegram.ps1 -Check`. Windows PowerShell 5.1 поддерживается;
сохраняйте скрипт в UTF-8 с BOM.

Если бот уже использует другой webhook, скрипт остановится.
Параметр `-ReplaceWebhook` разрешает перенос только по явному решению администратора.

## Отправка и ограничения

Cloud Scheduler вызывает `/internal/telegram/remind` каждые 5 минут с Google OIDC.
Анонимные запросы отклоняются. В Cloud Run проверяется служебная учётная запись,
а привязка Telegram создаётся только после подтверждения в личном аккаунте сайта.
Пользователь не передаёт произвольный ID получателя серверу.

Источник — подключённые задания Moodle. Целевой момент — срок минус 72 часа;
обычная задержка зависит от интервала проверки и времени запросов. Выполненные
задания пропускаются. Дедлайны с остатком меньше 72 часов на момент включения
не получают старых напоминаний. Временный сбой можно догнать до дедлайна, если
уведомления были включены заранее. Часовой пояс отображения — `Asia/Qyzylorda`.

Firestore хранит привязку, выключатель и состояния доставки. Повторные и
параллельные запуски используют устойчивые идентификаторы и аренду операции.
После неопределённого результата Telegram запрос не повторяется вслепую:
доставка ровно один раз внешним API не гарантируется. Уже начатая отправка
может завершиться после выключения переключателя.
