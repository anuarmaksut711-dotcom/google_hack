# Готовые кандидаты исправлений для Мерея

Эти patch-файлы подготовлены в разрешённой папке материалов. Они **не применены**
к зависимостям или backend-тестам рабочей ветки: действует первоначальное
разделение владения. Проверена только временная копия исходников.

База кандидатов: `codex/chat-pages-release`,
`c19aee8eba587e499f48de295e7700136023a595`.

## 0001: зависимости OAuth для чистого сбора тестов

`0001-include-declared-oauth-test-dependencies.patch` добавляет в
`requirements/test.lock` три уже объявленные зависимости с хешами:
`google-auth-oauthlib==1.5.0`, `requests-oauthlib==2.0.0`, `oauthlib==3.3.1`.
Всего девять добавленных строк; другие версии не меняются.

Lock получен закреплённым `uv==0.13.1` командой из README:

```sh
python -m uv --no-config pip compile pyproject.toml --all-extras --universal \
  --python-version 3.12.13 --constraint requirements/agent-linux.lock \
  --constraint requirements/dev.lock --generate-hashes --no-header --no-annotate \
  --output-file /tmp/campuspulse-test.lock
```

## 0002: проверка возможностей вместо старого утверждения о Calendar

`0002-check-recovery-actions-in-advice-mode.patch` убирает устаревшее требование
показывать «запись недоступна» в режиме чата. Вместо него тест требует отсутствия
recovery-кнопок approve/apply. Уже существующие проверки `runtime=false`, ссылки
на чат и запрета `POST /api/runs` сохраняются. Это не удаляет проверки доступа к
новым Calendar-планам: они находятся в их собственных тестах.

Патч 0002 относится к Calendar-ветке с новым renderer. В старом main без новой
функции изменение такого теста не требуется.

## Как принять

В рабочей ветке Мерея сначала сверить базу и рабочие изменения, затем проверить
patch-файлы до применения:

```sh
git apply --check presentation/pitch-2026-10-22/backend-candidates/0001-include-declared-oauth-test-dependencies.patch
git apply --check presentation/pitch-2026-10-22/backend-candidates/0002-check-recovery-actions-in-advice-mode.patch
```

Путь предполагает, что материалы уже доступны в этой рабочей копии. Применение,
коммит и объединение остаются за владельцем соответствующих файлов. После
применения нужна чистая установка через `--require-hashes`, полный Linux CI и
отдельная приёмка опубликованной версии.

archive указанного SHA. Полный прогон с Firestore Emulator: **2184 passed,
14 skipped**, 35 warnings, 145.83 s. Отдельно шесть целевых OAuth/UI проверок:

Это проверка исходников кандидата, а не опубликованного приложения.

## Остальные backend/cloud задачи

- Для `.live_mcp` нужен реальный legacy factory/исходник из serving image либо
  воспроизводимая закреплённая композиция. Подставлять пустой MCP или менять IAM
  ради зелёного startup нельзя. Готовый безопасный патч без этого исходника
  подготовить невозможно.
- Контекст чата должен получать авторизованные planning/Calendar факты через
  существующую проекцию; статический текст сейчас им противоречит.
- `solve_repair` должен публиковать настоящее safe-событие в существующий trace.
  UI не должен имитировать успешный вызов.
- Нужен `setup/PITCH-CLOUD-HANDOFF.md` и реальный полный recovery сценарий.

Отказ необязательной UI-проекции/evidence уже обработан в `web/views/` UI-ветки.
Он не требует менять `AccountFeed` для доступности сохранённой карточки. Ошибки
чтения самого плана, доступа и привязки по-прежнему запрещают отображение.
