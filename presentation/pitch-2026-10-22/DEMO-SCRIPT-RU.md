# Демонстрация на 2–3 минуты

Основной локальный показ использует `connected_browser_fixture.py` на порту 8964.
Это фактическая композиция cloud-приложения с синтетическими Google identity,
Moodle HTTP, Engine, OCR и Calendar/MCP. Предупреждение о тестовом режиме остаётся
видимым. Стенд не проверяет GCP, реальный OCR или личный Calendar.

Запуск из корня:

```sh
PYTHONPATH=src:. .venv-pitch/bin/python tests/pitch_ui/connected_browser_fixture.py
```

Открыть `http://127.0.0.1:8964/fixture/start`. Часы: 17.10.2026 21:00 Asia/Almaty.
Контрольный запрос: «Составь расписание: 22:30–23:30, 60 минут».

| Время | Действие и реплика |
| --- | --- |
| 0:00–0:20 | Открыть задания. «CampusPulse читает дедлайны Moodle. Сейчас это локальный тест, поэтому данные и внешние сервисы искусственные». |
| 0:20–0:55 | Открыть страницу пар. Добавить вручную одну тестовую пару вне 22:30–23:30, указать период 17–24 октября. При показе импорта проговорить, что OCR стенда возвращает контролируемую тестовую строку. «Распознавание заполняет черновик. Скриншоты следующих дней дополняют его». |
| 0:55–1:10 | Проверить предметы, дни и время, подтвердить всю неделю и сохранить. «Невидимые дни сами по себе не означают отсутствие пар. Даты действия указывает студент». |
| 1:10–1:35 | В чате отправить контрольный запрос. Показать фактические `read_assignments` и `read_schedule`. «Модель читает данные и предлагает блок. Backend проверяет его и создаёт предложение Calendar». |
| 1:35–2:00 | Открыть предложение Calendar, проверить 22:30–23:30. Согласовать точную версию, затем отдельно применить. «У модели нет инструментов записи. Это действие backend после моего согласия». |
| 2:00–2:30 | Показать статус verified и фактические apply/verify. «Система перечитала созданное событие. Сообщения модели для этого недостаточно». |
| 2:30–2:50 | Обновить страницу и повторить apply того же плана, если действие доступно. Показать receipt: `calendar_mutations = 1`. «Повтор не создаёт дубликат. Живую облачную запись новой версии принимаем отдельно». |

При unavailable, unknown, partial или verification_failed назвать фактический
статус, перечитать состояние и не повторять запись вслепую. При ошибке импорта
использовать ручной ввод. Для гарантированного короткого показа заполнить пары
вручную, а составление черновика показать отдельно.

Облачный показ использует штатный Google-вход и выделенный разрешённый Calendar.
Перед ним сверить serving source и итоговый live receipt. Подтверждённый
read-only релиз 1382f49 сам по себе не доказывает новую запись Calendar или OCR.
Личные скриншоты, feed URL и токены не попадают в запись и репозиторий.
