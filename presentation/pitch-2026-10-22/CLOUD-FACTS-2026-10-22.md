# Облачные сведения для защиты

## Подтверждённый read-only релиз

Источник: `setup/PITCH-CLOUD-HANDOFF.md`, source
`1382f49aaba7c37c6571bbd8355349064e039012`.
[Handoff в GitHub](https://github.com/anuarmaksut711-dotcom/google_hack/blob/1382f49aaba7c37c6571bbd8355349064e039012/setup/PITCH-CLOUD-HANDOFF.md).

Handoff фиксирует успешный Cloud Build, обновление существующего managed Agent
Engine и опубликованные website/private MCP. 22 октября пользователь вошёл в
реальный сайт и выполнил два запроса. Фактический `read_assignments` вернул
15 записей Moodle. Запрос плана также вызвал `read_schedule`, который вернул
`not_connected`: пары ещё не были сохранены. Ответ корректно остался черновиком.
`agent_run_id` и фактический `tool_trace` сохранились в истории чата.

Путь чата: Cloud Run вызывает приватный `async_query(invocation, service_token)`.
ADK-модель выбирает только `read_assignments()` и `read_schedule()` через MCP.
Владелец и живая сессия определяются сервером. Модель не получает feed URL,
учётные токены или выбор аккаунта. Этот study-agent не имеет инструментов записи.

## Новая объединённая версия

Локально объединены актуальный main и UI. `StudyConversation` сохраняет managed
путь и делегирует ограниченное распознавание файлов существующему импортёру.
Сервер типизирует `AdviceReply`, заново читает сохранённые пары и проверяет блоки.

Если пользователь подключил Calendar с нужным разрешением, backend через
приватный MCP читает занятость и создаёт неизменяемое предложение `ConnectedPlans`.
Согласие привязано к `plan_id` и `payload_hash`. Действие пользователя запускает
backend writer и приватные MCP `apply_plan` / `verify_plan`. Модель ими не управляет.
Перед согласованием и записью backend проверяет текущую базу пар и Calendar.
Изменение пар делает прежний план устаревшим. Verify перечитывает фактический результат.

Локальный `connected_browser_fixture.py --check` подтвердил одну запись, verify
и повтор без дубликатов с тестовыми внешними границами. Это не доказательство работы реального Google Calendar.
Реальный настроенный Vertex Gemini отдельно распознал один исходный скриншот
через адаптер: четыре видимые пары понедельника, даты null, без выдуманных дней.
Это не вызов website HTTP и не измерение точности OCR.

**Облачная приёмка новой записи Calendar и распознавания ещё не завершена.**
Не переносите успешный read-only rollout на новые функции без итогового live receipt.
